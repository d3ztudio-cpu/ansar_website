# Library post rule review — 2026-10-23

## Write path reviewed

`AdminLibrary.jsx` creates and updates `libraryPosts`.  The client always sends the explicitly enumerated Library fields, including `type`, title, description (`summary`), publication state, and server timestamps.  Short Film entries use the same path and store a video URL in `linkUrl`.

## Observed denial cause

The Short Film UI allowed a pasted description with no client-side character cap, while `isValidLibraryPost` allowed `summary` only through 1,500 characters.  A longer synopsis failed rule validation and Firestore returned the intentionally generic `permission-denied` response.

## Change and security assessment

The bounded description allowance is now 10,000 characters both in the UI and in the rule.  No authorization scope was widened: writes remain limited to an authenticated Library editor or established admin; the strict allowed-field list, URL validation, publication boolean, and server timestamp validation are retained.

## Adversarial checks

- Unauthenticated Library write: denied by `isAuthenticated` through the editor/admin checks.
- Non-Library authenticated user write: denied by the editor/admin checks.
- Extra document field: denied by `hasOnlyAllowedFields`.
- Oversized description: denied above 10,000 characters by UI and rule.
- Invalid URL/type/timestamps: denied by the existing validators.
